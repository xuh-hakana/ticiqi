## 1. 现状诊断（为什么会"乱到没法提建议"）

**已核实（2026-11-17 实机截图 + 代码核对，更正初稿错误）**：`theme.css:298+` 已把 prompter 模式下命令方块外壳（topbar/sidebar/explorer/statusbar）隐藏；`app.js:3691 initPrompterOnly()` 直接进提词器数据。所以**打开第一屏已经是提词器需求库，不是命令方块欢迎页**——初稿这条诊断错误，作废。

真正的问题收窄到一处：**三视图本身没按逐字原文做**。实机截图（`/tmp/ticiqi-verify/01-文字视图.png`）显示的三视图缺陷：

| 原文要求 | 现状 | 违背 |
|---|---|---|
| 59 行"像选星星、外部看标题、点击看内容、游戏感炫酷、不要一板一眼文件夹" | 星图是无边记式矩形卡片+网格线，像看板不像星空 | 违背 |
| 61 行"星图展开预览后才显示文件/文件夹" | 没有展开预览态；星图卡片直接点就进文字 | 未实现 |
| 61 行"文字模式看父级同级子级并能点击切换，可回星图/切文件夹" | 文字详情没有父/同级/子级导航，三视图是三个割裂 pane，切视图丢选中 | 未实现 |

| 63 行"搜索优先定位待办和想法的标题" | 搜索是标题+原文+标签混合匹配，无优先级 | 部分 |

结论：外壳已经对了，**不用动 boot.js / theme.css / 命令方块遗留**。这一轮只重做三视图（星图选星星+展开预览、就地互切、父/同级/子级、背景小星星、搜索优先标题），其余功能零改动。

## 3. 三视图关系（核心，按 57/59/61 行）

三个是**同一需求的三种看法**，在同一位置互切，不是三个独立页面：

```
        ┌──────── 星图（选星星·默认）────────┐
        │ 需求=星星，外部看标题，背景小星星滑动 │
        │ 拖拽移动 · 同分类成簇连线          │
        └──────┬──────────────┬────────────┘
               │点击星星→展开预览│  ← 展开预览才显示文件/文件夹
               ▼              │
        ┌──────── 文字 ────────┴──┐
        │ 详情：父级/同级/子级 可点切 │
        │ 六段 · 体检分 · 原文复制    │
        │ 含打开的文件/文件夹        │
        └──────┬──────────────┬───┘
               │回星图         │切文件夹
               ▼              ▼
        ┌──────── 文件夹 ──────────┐
        │ 需求树：分类→六段，可打开文件/文件夹 │
        └────────────────────────┘
```

- 切换保持**当前选中的需求**（同一位置），不丢上下文。
- 三个模式顶部都有入口打开关联文件/文件夹（星图仅展开预览时显示）。
- 顶栏三按钮 + 视图内快捷切换并存。
