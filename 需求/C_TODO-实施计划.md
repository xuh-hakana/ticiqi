# C_TODO 全量分阶段实施计划

这是干什么的：把提词器原先拆成三块的需求库（`prompts.json`）/ 遗留问题（`issues.js`）/ 已完成区（`C_DONE.jsonl`）统一成规格要求的 **SQLite 树形需求内核**。覆盖《文档四·MVP spec》的 spec_00~35 共 36 项。

来源：`需求/文档三“状态机”的“AI清理”条目有引用。原文：.zip` 内《文档四：MVP spec》《软件本身应有内容》《用户使用逻辑》。用户 2026-11-15 授权「可用依赖都能装，可后期修改」，技术选型由 AI 定。

## 落地原则（全程不动）

| 原则 | 含义 | 出处 |
| --- | --- | --- |
| 单一数据源 | SQLite 是唯一真相；`C_TODO.md`/`C_DETAIL`/索引/文件层全部由代码生成，不手工维护双份 | 规格「存储」；`说明.md` §7 |
| 客户端内可看可改 | 状态、开关在提词器客户端（`.app` + `web/`）里能看能改 | 用户长期规矩 |
| 省 token | 同步/索引/报告解析靠代码完成，不写进提示词；每阶段都在减少 AI 每轮 token | `说明.md` §7 触发原话 |
| 改动范围锁定 | 只改当阶段指定文件；动手前先列清单；顺带优化只记录不修改 | 规格「开发 Agent 行为约束」原文 |
| 三视图同源 | 星图/文字/文件夹是同一棵树的不同呈现，搜索与「含失效」三视图同步 | 规格「三视图」 |
| 事务性 | 写操作失败回滚，不进失效，报错提示 | spec_22 |

| 项 | 决定 | 理由 |

| 接入规则 | 只读 `需求/文档一-AI接入规则.md` 正本 | 已是逐字正本，不复制、不改写 |
| 版本初值 | 2.8.0（settings.ticiqiVersion） | 规格指定 |
